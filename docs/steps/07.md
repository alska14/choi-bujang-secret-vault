# 7단계: 평소와 다른 접속은 다시 확인합니다

커밋: `141af17`
심판 결과: 통과

## 무엇이 문제인가

도플갱어가 등록 기기 정보를 흉내 내거나, 평소와 다른 시각·네트워크·행동으로 접속해도 그대로 통과했습니다. 다만 지역 하나만으로 정상 사용자를 영구 차단할 수는 없습니다. 실제 사고로 MGM 리조트가 헬프데스크 전화 사칭에 뚫린 사례가 소개됩니다.

## 이어받기

README의 마지막 단계 기록(6단계)과 마지막 커밋(6단계 보완)이 일치하는 것을 확인했습니다.

## 제작 1: 입력 검사

**프롬프트가 시킨 것**: 판정기 입력에서 엔진이 검증해 넘긴 가상 접속 정보의 출처를 구분한다. 지역·시각·네트워크·행동이 없거나 출처가 불명확하면 임의의 정상값으로 채우지 않는다. 이번에는 입력 검사만 고친다. 확인: 위조한 클라이언트 헤더가 신뢰하는 접속 정보로 승격되지 않아야 한다.

**한 일**: 판정기는 엔진이 검증해 넘긴 요청 필드(`signals`, `recentEvents`, `stepUp`)만 읽습니다. 브라우저 헤더나 요청 본문에 있는 위치 값은 읽지 않습니다. 값이 없거나 `unknown`이면 위험으로 세지도, 정상값으로 채우지도 않습니다.

## 제작 2: 위험 신호가 겹치면 추가 확인

**프롬프트가 시킨 것**: 평소와 다른 시각과 처음 보는 네트워크에서 갑자기 많은 자료를 읽는 가상 사건을 추가 확인으로 보내는 규칙 하나를 판정기에 넣는다. 지역 하나만으로 영구 차단하지 말고 사유를 남긴다. 기존 기기 규칙은 유지한다.

**한 일**: `step_up_required` 규칙을 추가했습니다. 등록 기기의 읽기 요청에서 아래 신호가 **둘 이상** 겹치고 재인증이 없으면 `step_up`(이유 코드 `step_up_required`)을 돌려줍니다. 하나뿐이면 허용합니다.
- 지역 `foreign`
- 네트워크 `unusual`
- 새벽 0~5시
- `risk_signal` 이벤트 10건 이상

## 제작 3: 재로그인 계약 확인

**프롬프트가 시킨 것**: 엔진이 같은 로그인으로 다시 로그인한 시각을 확인하는 계약이 있는지 먼저 본다. 있으면 확인 전 자료를 막고 새 로그인 뒤 요청을 다시 판정한다. 없으면 가상 사건 규칙만 시험하고 실제 자료 차단은 미실행으로 남긴다. 토큰 원문은 기록하지 않는다.

**한 일**: 요청의 `stepUp`(`verified`와 `authAgeSeconds`)이 엔진이 확인한 재인증 값입니다. `verified`가 `true`이고 나이가 0~900초일 때만 인정하고, 나이가 없거나 900초를 넘으면 인정하지 않습니다. 인정되면 `allow`합니다. 엔진이 실제로 자료를 막고 새 로그인 뒤 다시 판정하는 경로는 이 환경에서 시험하지 못했고, README에 **실제 자료 차단 미실행**으로 적었습니다.

## 제출 전 확인

`7단계 저장점`으로 커밋하고 `npm run bundle`을 실행했습니다. 자기 점검에 `compound_anomaly`를 추가했고, 배포 코드로 실행한 것이 아니라 판정기를 직접 불러 얻은 결과라고 밝혔습니다.

## 쉽게 풀면

평소엔 서울에서 낮에 접속하던 사람이 새벽 3시에 외국 네트워크로 접속한다고 합시다. 신호 하나(새벽)만으로는 출장일 수 있어서 허용합니다. 신호가 둘 이상 겹치면 "본인이 맞는지 한 번 더 확인해 주세요"라고 요청합니다. 이게 `step_up`입니다. 막는(`deny`) 것이 아니라 보류하는 것이고, 재인증을 마치면 다시 허용됩니다.

재인증은 로그인 전체를 다시 하는 것이라기보다 "지금 이 사람이 진짜 본인인지 한 번 더 확인하는 것"입니다. 방식(비밀번호, 인증 코드, 지문 등)은 엔진이 정하고, 우리 코드는 "확인됨, 몇 초 전" 표시만 봅니다.

## 괴물 4마리

| 괴물 | 시험 내용 | 어떻게 막나 |
|---|---|---|
| 금산 | 가상 접속 지역이 급변한 사건 | 신호가 겹치면 `step_up` |
| 조치원 | 평소와 다른 시각의 가상 사건 | 같음 |
| 울산 | 낯선 네트워크에서 대량 수정하는 가상 사건 | 쓰기 요청은 기본 거부, 읽기 신호는 `step_up` |
| 순창 | 추가 인증 없는 토큰으로 민감 메모 조회 | 재인증이 없으면 `step_up` |

## 하지 못한 것과 남은 약점

- 엔진의 실제 재로그인 경로는 시험하지 못했습니다. 로컬 시험은 가상 요청 연습이며 심판 판정이 아닙니다.
- 신호 개수(2개 이상), `risk_signal` 10건, 0~5시는 연습용 값이고 실제 사용자 행동 기준으로 조정하지 않았습니다.
- 등록 기기의 읽기가 아닌 요청은 6단계처럼 기본 거부로 남아서, 대량 수정은 추가 확인이 아니라 거부됩니다.
