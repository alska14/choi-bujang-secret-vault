# 방어전 단계별 기록

일부러 뚫려 있는 가상 자료실을 한 단계씩 막아 가는 과정을 단계별 파일로 나눠 적었습니다. 파일마다 무엇이 문제였는지, 제작 프롬프트가 시킨 것과 실제로 한 일, 쉬운 풀이, 하지 못한 것과 남은 약점을 담았습니다. 전체를 한 장으로 보려면 [../DEFENSE_STEPS.md](../DEFENSE_STEPS.md)를 보세요.

이 문서에는 비밀번호, 토큰, API 키 값을 적지 않습니다. 키는 모두 Vercel 환경변수에만 있습니다.

"기록 없음"은 이전 작업에서 진행한 단계라 이번 기록 작업에서 결과를 확인하지 못했다는 뜻입니다. 1~5단계 파일은 README의 기록을 근거로 정리했고 제작 번호로 나누지 않았습니다. XDR 보너스 6개 모듈(`brute-force`, `web-injection`, `known-cve`, `persistence`, `privilege`, `exfiltration`)을 모두 만들었습니다.

## 공통으로 배운 것

- 방어는 한 겹이 아니라 겹겹입니다. 로그인(3), 소유자(4), 직접 접근 차단(5), 기기(6), 이상 징후(7), 구역(8), 탐지(9), 복원(10), 앱(11)이 각각 다른 구멍을 막습니다.
- 판정자가 격리된 환경에서 코드를 따로 실행할 수 있어서, 보너스 `decide.mjs`는 다른 파일에 기대지 않는 단독 파일이어야 했습니다.
- 로컬 시험(`decider:test`, 변형 경보 시험 등)은 연습입니다. 실제 엔진 경로와 심판 판정을 대신하지 못합니다.
- 프롬프트와 계약이 어긋나면(예: 네트워크 값이 없는 사건, 메모 주인이 없는 요청) 계약에 있는 값만 쓰고, 어긋난 부분은 각 파일의 "프롬프트와 다르게 한 점"에 적었습니다.
