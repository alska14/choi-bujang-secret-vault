# 1단계: 일부러 뚫린 출발점

> 이 단계는 이전 작업에서 진행했습니다. 제작 프롬프트 원문은 이번 기록 작업에서 보지 못해서, README의 기록을 근거로 정리했습니다. 제작 번호는 나누지 않았습니다.

## 무엇이 문제인가

시작 틀을 그대로 배포하면 가상 메모가 `/data.json`에 공개됩니다. 누구나 주소만 알면 자료를 읽을 수 있는 상태입니다. 1단계는 이 상태를 "일부러 뚫린 사이트"로 제출하는 단계이고, 이후 단계가 하나씩 구멍을 막습니다.

## 한 일

README의 "학생이 하는 일: 세 걸음"을 따랐습니다.

1. GitHub 계정을 만듭니다.
2. 방어전 1단계 카드의 Deploy 버튼으로 Vercel에 배포합니다. 새 저장소가 본인 계정의 Public 저장소인지 확인합니다.
3. 배포가 끝나면 나온 `https://…vercel.app` 주소를 1단계 카드에 붙여넣고 제출합니다.

배포가 끝나면 `/`에서 점령된 가상 자료실이 보이고, `/data.json`에 같은 가상 메모가 공개됩니다.

## 쉽게 풀면

금고 문을 일부러 열어 둔 채로 시작하는 단계입니다. 어디가 열려 있는지 눈으로 확인해야 이후에 하나씩 잠글 수 있습니다.

## 시작 틀이 자동으로 하는 일

- `vercel.json`이 정적 결과물 `public`을 배포합니다.
- 빌드(`npm run build`)가 Vercel이 주는 저장소 소유자·이름, 커밋 번호, 배포 주소를 검증해 `public/aleph.json`을 만듭니다. 값이 없으면 빌드가 실패해서, 성공한 척 빈 주소를 내보내지 않습니다.
- `aleph.json`만으로 저장소 소유나 방어 성공을 인정하지는 않습니다. 심판이 공개 저장소의 실제 커밋과 배포된 자료를 따로 대조합니다.

## 주의

- 가상 메모에는 실제 개인정보, 토큰, 비밀키를 넣지 않습니다.
- 로컬에서만 화면을 볼 때는 `npm run build -- --local`을 씁니다. 로컬 실행은 Vercel 배포나 심판 접수를 증명하지 않습니다.
