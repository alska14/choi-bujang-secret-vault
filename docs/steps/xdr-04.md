# 보너스 xdr-04: 몰래 심어진 프로그램을 찾아냅니다

커밋: 보너스 xdr-04 저장점
심판 결과: 아직 제출하지 않았습니다.

## 무엇이 문제인가

최 부장 PC에 서명 없는 새 서비스와 예약 작업이 조용히 생겼습니다. 다시 켜도 살아남으려고 심어 둔 프로그램입니다. 실제 사고로 솔라윈즈 오리온 업데이트에 숨은 선버스트 백도어 사례가 소개됩니다.

만들 것은 파일 무결성 경보와 서비스·예약 작업 생성 경보를 모아, 평소 목록에 없는 항목을 알리고 명확한 경우에만 막을 후보로 올리는 모듈입니다. 판정기 규칙을 대신하지 않습니다.

## 이어받기

README의 마지막 단계 기록(12단계 보완)과 마지막 커밋(보너스 xdr-03 저장점)이 어긋나지 않는 것을 확인했습니다. `xdr/persistence/`는 비어 있었고 경보 묶음은 24건(`xdr/fixtures/persistence.json`)이었습니다. 아무 파일도 고치지 않았습니다.

## xdr-03과 같은 원칙

이번 프롬프트도 `decide.mjs`에 엄격합니다. 심판이 인터넷 없이 `decide.mjs` 한 파일만 불러와 경보마다 바로 답을 받습니다.

- Jev를 부르지 않고, `decide.mjs`에 import 문이 없고, 파일·네트워크도 쓰지 않습니다. 패턴은 파일 맨 위 상수입니다.
- 읽기 모듈은 확인용이라 `decide.mjs`가 불러오지 않는 별도 파일입니다.
- 위험도 10 이상은 block, 5~9는 alert라는 바닥 기준을 처음부터 넣었습니다.

## 제작 1: 경보 읽기

**프롬프트가 시킨 것**: `xdr/fixtures/persistence.json`의 Wazuh 경보를 읽어 시각·출발 주소·계정·규칙 수준·설명만 뽑는 읽기 모듈을 `xdr/persistence/read-alerts.mjs`로 만든다. 원본 경보는 고치지 않고 비밀값처럼 보이는 값은 출력하지 않는다. 이 모듈은 확인용이라 `decide.mjs`가 불러오지 않게 따로 둔다. 확인: 경보 건수와 뽑은 줄 수가 같아야 한다.

**한 일**: 경보 24건에서 24줄을 뽑습니다. 파일 경로 같은 나머지 값은 뽑지도 출력하지도 않습니다.

## 제작 2: 패턴 목록

**프롬프트가 시킨 것**: 이 공격의 알려진 형태를 `xdr/persistence/patterns.json`으로 정리한다. 근거는 MITRE ATT&CK T1543(시스템 프로세스 생성·변경), T1053(예약 작업)이고 신호는 서명 없는 새 서비스 등록, 낯선 예약 작업, 시작 폴더 변경 정도다. 패턴마다 이름·찾는 조건·근거를 한 줄씩 적고 근거 없는 패턴은 넣지 않는다.

**한 일**: 패턴 9개를 근거 한 줄씩과 함께 정리했습니다.

| 패턴 | 확신도 | 뜻 |
|---|---|---|
| 서명 없는 서비스 등록·변경 | 0.95 | 서명 없는 새 서비스, 실행 파일이 바뀌고 서명이 없음 |
| 낯선 예약 작업 | 0.93 | 처음 보는 예약 작업, 이름이 임의 문자열 |
| 시작 폴더 변경 | 0.93 | 시작 폴더에 평소 목록에 없는 프로그램 |
| 다시 켜도 남도록 등록된 새 서비스 | 0.93 | 재시작 뒤에도 살아남도록 등록 |
| 높은 위험도의 지속성 경보 | 0.90 | 위험도 10 이상 |
| 시작 폴더 경로의 파일 | 0.70 | 로그인 때마다 실행되므로 사람이 확인 |
| 임시 폴더의 실행 파일 | 0.60 | 흔한 은닉 위치지만 그것만으로 단정 못 함 |
| 서명을 아직 확인하지 못한 항목 | 0.55 | 서명이 없다고 확인된 것이 아님 |
| 중간 위험도 경보 | 0.55 | 위험도 5~9 |

경보 묶음에는 "서명된 채로 실행 중"이라는 정상 경보와 "서명은 확인되지 않았습니다"라는 애매한 경보가 있어서, "서명" 글자만 보면 오탐이 납니다. 그래서 "서명 없는", "서명이 없습니다"만 명확한 신호로 보고 "서명은 확인되지 않았습니다"는 알림(alert) 신호로 따로 두었습니다.

## 제작 3: 판정 모듈

**프롬프트가 시킨 것**: 패턴을 `decide.mjs` 맨 위에 상수로 옮겨 적고, 그 패턴과 경보를 맞춰 판단하는 `decide(alert)` 하나를 내보낸다. 반환은 `{action, confidence, reason}`이고 확신도 0.85 이상은 block, 0.5 이상은 alert, 그 아래는 record다. `reason`에는 근거 패턴 이름을 한 줄로 적는다. 다른 파일이나 패키지를 불러오지 않고, 파일을 읽거나 쓰지 않고, 바깥에 묻지 않고 혼자 계산한다. 확인: 명확한 공격은 block, 애매한 건 alert, 정상 이벤트는 record로 나뉘어야 하고 `decide.mjs`에 import 문이 없어야 한다.

**한 일**
- `patterns.json`과 같은 내용을 파일 맨 위 상수로 넣고 두 곳이 같은지 시험합니다.
- 경보 설명의 문구와 경로 모양(임시 폴더, 시작 폴더)을 함께 봅니다. 경로 값은 판단에만 쓰고 결과에는 담지 않습니다.
- 서로 다른 강한 신호(확신도 0.85 이상)가 둘 이상 겹치면 확신도를 조금 올립니다.
- `decide`만 내보내고, 이유에는 패턴 이름만 담습니다.

## 제작 4: 알림과 차단

**프롬프트가 시킨 것**: `xdr/persistence/respond.mjs`를 새로 만들어 `decide` 결과 가운데 차단 후보만 ZTNA 판정기의 거부 규칙으로 넣는 연결을 만든다. 규칙에는 만료 시각과 근거 경보 번호를 붙이고 정상 사용자를 막는 규칙은 넣지 않는다. 알림은 같은 파일에서 `xdr/alerts.log`에 한 줄씩 쌓는다. `decide.mjs`는 판단 결과만 돌려주고 파일 쓰기·판정기 연결은 하지 않는다. 판정기의 기존 규칙은 고치지 않는다.

**한 일**: `respond.mjs`가 알림을 `[persistence]` 접두사로 `xdr/alerts.log`에 쌓고(네 모듈의 줄이 모두 보존됨), 차단 후보를 `block-rules.json`에 적습니다. 후보는 7개 주소이고 규칙마다 만료 시각(경보 시각 + 1시간)과 근거 경보 번호가 있습니다. 정상 판정이 난 주소는 후보에서 뺍니다.

**프롬프트와 다르게 한 점**: 판정기의 요청에는 접속 주소가 없고 계약에 없는 필드를 만들면 안 되어서, 차단 후보는 파일로만 만들고 판정기에 연결하지 않았습니다(앞의 모듈들과 같습니다).

## 제출 전 확인

`npm run xdr:run -- persistence`를 다시 실행해 `result.json`을 갱신하고 「보너스 xdr-04 저장점」으로 커밋합니다. 시험 10개(`xdr/persistence/variants.test.mjs`)가 통과했습니다. 위험도가 낮아도 명확한 문구는 block, 서명 미확인·임시 폴더 파일만 있으면 alert, 서명된 정상 서비스는 record, 필드가 빠진 경보는 오류 없이 record인지, 파일 하나만 복사해도 8/8/8인지, 소스에 import·파일·네트워크 사용이 없는지 확인합니다.

## 쉽게 풀면

누가 컴퓨터를 다시 켜도 자기 프로그램이 저절로 실행되게 몰래 설정해 두는 것이 이 공격입니다. 서비스 등록, 예약 작업, 시작 폴더가 그 통로입니다. 서명이 없는 새 서비스를 등록하거나, 처음 보는 예약 작업을 만들거나, 시작 폴더에 낯선 프로그램을 넣으면 확실한 공격으로 봅니다. 수업 중에 만든 예약 작업이나 임시 폴더의 파일 하나는 공격이 아닐 수 있어서 알림만 남깁니다.

## 하지 못한 것과 남은 약점

- 차단 후보를 ZTNA 판정기에 실제로 연결하지 않았습니다. 후보는 파일로만 있습니다.
- 판정자의 정답표는 보지 못했습니다. 우리 기준이 정답표와 같다는 보장은 없습니다.
- 경로를 임시 폴더(temp, tmp)와 시작 폴더 모양만 봅니다. 다른 은닉 위치나 운영체제별 경로는 보지 않습니다.
