# 6단계: 등록된 기기만 자료실에 들어갑니다

커밋: `f05d669`(저장점), `62e5ad4`·`6ccd3ac`(보완)
심판 결과: 괴물 4마리 모두 격파

## 무엇이 문제인가

도플갱어(진짜 사용자를 흉내 내는 가짜)가 비밀번호로 로그인해도, 등록되지 않은 기기에서는 자료를 받지 못해야 합니다. 로그인만 확인하던 지금까지는 남의 기기에서 들어와도 자료를 받았습니다. 실제 사고로 우버 외주 직원 계정이 반복 승인 요청에 뚫린 사례(2022)가 소개됩니다.

## 이어받기

README의 마지막 단계 기록이 5단계이고 마지막 커밋과 맞는 것을 확인했습니다. 아무 파일도 고치지 않았습니다.

## 제작 1: 요청에서 기기 등록 여부가 어디로 들어오는지

**프롬프트가 시킨 것**: `docs/DECIDER_REQUEST.md`를 읽고 판정 요청에서 사용자와 기기 등록 여부(`deviceRegistered`)가 어디에 들어오는지 한 줄씩 설명한다. 인증서·CA·서명 키를 새로 만들거나 Git에 넣지 않는다. 아직 판정기 규칙은 바꾸지 않는다.

**한 일**: 읽기만 했습니다. `deviceRegistered`는 판정 요청의 18개 항목 중 하나이고, 반 엔진이 기기 등록 여부를 확인해서 요청에 담아 보냅니다. 실제 릴레이는 미등록 기기를 판정기보다 먼저 막고, `false`는 심판의 가상 요청에서만 올 수 있습니다. 새 키 파일이나 비밀값은 만들지 않았습니다.

## 제작 2: `device_registered` 규칙 하나

**프롬프트가 시킨 것**: `src/decider.mjs`에 요청의 기기가 등록 상태(`deviceRegistered`)일 때만 자료 읽기를 허용하는 규칙 하나를 넣는다. 규칙 ID는 `device_registered`로 `RULE_IDS`에 추가한다. 미등록이거나 값이 없으면 `deny`와 이유 코드 `device_not_registered`로 거부한다. 다른 규칙은 건드리지 않는다.

**한 일**: `deviceRegistered`가 정확히 `true`이고 동작이 읽기(GET)일 때만 `allow`합니다. `false`, 값 없음, 이상한 값은 모두 `device_not_registered`로 거부합니다. 그 밖의 요청은 시작 틀의 기본 거부(`starter.deny`)로 남습니다.

**프롬프트와 다르게 한 점**
- 처음에는 허용 이유 코드를 `approved`로 썼습니다. 이 코드는 문서 예시일 뿐 운영 허용 목록에 있다는 보장이 없어서, 강사 통과용 표본이 쓴 `device_registered`로 바꿨습니다(보완 커밋 `6ccd3ac`).

## 제작 3: 시험으로 확인

**프롬프트가 시킨 것**: `npm run decider:test`를 실행해서 "등록 기기의 정상 요청"이 통과하고 "미등록 기기의 가상 요청"이 `deny`와 `device_not_registered`로 나오는지 보여 준다. 확인 순서를 README에 적는다. 설치 명령은 짓지 않는다.

**한 일**: 두 항목 모두 통과했습니다. 값이 없는 경우, 등록 기기의 POST 요청도 따로 확인했습니다(값 없음은 `device_not_registered`, 등록 기기의 POST는 기본 거부). README에 6단계 절과 다시 실행하는 법을 적었습니다.

## 제출 전 확인

`6단계 저장점`으로 커밋하고 `npm run bundle`을 실행했습니다. 첫 실행에서는 `bundle-notes.json`(커밋하지 않는 로컬 파일)이 없어서 오류가 났고, 만들어서 해결했습니다. 직접 점검 호출 한 줄이 빠진 것을 발견해 보완 커밋(`62e5ad4`)으로 고쳤습니다.

## 쉽게 풀면

로그인은 "당신이 누구인지"를 확인하는 것이고, 이 단계는 "어느 기기에서 왔는지"를 한 번 더 확인하는 것입니다. 로그인을 막는 게 아니라 로그인한 뒤 자료를 요청하는 단계에서 막습니다. 비밀번호를 훔쳐 로그인해도 남의 기기라면 자료가 열리지 않습니다.

기기가 실제로 등록됐는지는 엔진이 확인하고, 우리 코드는 엔진이 알려 준 값을 보고 허용 또는 거부만 정합니다.

## 괴물 4마리

| 괴물 | 시험 내용 | 막는 곳 |
|---|---|---|
| 나태한해태 | 미등록 기기 인증서로 자료실 조회 | 엔진이 `deviceRegistered=false`로 전달하고 우리 규칙이 거부 |
| 6쪽마누라 | 클라이언트 인증서 없이 mTLS 통로로 요청 | 엔진(연결 단계) |
| 김보성녹차 | 등록 기기와 다른 사용자 토큰 조합 | 엔진과 4단계 소유자 검사 |
| 청양후추 | 판정기에 등록되지 않은 가상 기기 사건을 직접 입력 | 우리 `decide`가 직접 시험받음 |

## 하지 못한 것과 남은 약점

- 실제 배포에서 등록 기기 화면을 눌러 본 시험은 하지 못했습니다. `decider:test`는 가상 요청 연습이며 심판 판정이 아닙니다.
- 등록 기기의 GET이 아닌 요청(추가·수정·삭제)은 이 규칙이 허용하지 않아 기본 거부로 남습니다.
- `deviceRegistered`가 실제로 참인지는 엔진이 확인합니다. 엔진 확인이 틀리면 판정도 틀립니다.
