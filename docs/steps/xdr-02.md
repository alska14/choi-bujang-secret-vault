# 보너스 xdr-02: 웹 주입 공격을 잡아 냅니다

커밋: `5c73159`(저장점), `21f6683`(알림 로그 공유 보완)
심판 결과: 100점

## 무엇이 문제인가

최 부장 PC의 웹 로그에 주소창과 입력 칸으로 명령문을 밀어 넣으려는 요청이 섞여 들어옵니다. 실제 사고로 무브잇(MOVEit) 파일 전송 프로그램의 SQL 주입 취약점이 대량 악용된 사례가 소개됩니다.

만들 것은 웹 접근 경보에서 SQL 주입·스크립트 주입 형태를 가려내 알리고, 같은 주소에서 반복되는 명확한 주입 시도만 막을 후보로 올리는 모듈입니다. 판정기 규칙을 대신하지 않습니다.

## 이어받기

xdr-01과 같은 방식으로 폴더와 git 상태를 읽었고, 아무 파일도 고치지 않았습니다. 경보 묶음은 26건(`xdr/fixtures/web-injection.json`)이었습니다.

## 제작 1: 경보 읽기

**프롬프트가 시킨 것**: `xdr/fixtures/web-injection.json`의 Wazuh 경보를 읽어 시각·출발 주소·계정·규칙 수준·설명만 뽑는 읽기 모듈을 `xdr/web-injection/read-alerts.mjs`로 만든다. 원본 경보는 고치지 않고 비밀값처럼 보이는 값은 출력하지 않는다. 확인: 경보 건수와 뽑은 줄 수가 같아야 한다.

**한 일**: xdr-01과 같은 읽기 모듈을 만들었습니다(경보 26건, 뽑은 줄 26줄).

## 제작 2: 패턴 목록

**프롬프트가 시킨 것**: 이 공격의 알려진 형태를 `xdr/web-injection/patterns.json`으로 정리한다. 근거는 MITRE ATT&CK T1190(외부 공개 앱 악용)이고 신호는 요청 인자 안의 SQL 구문, 스크립트 태그, 경로 거슬러 올라가기(`../`) 반복이다. 패턴마다 이름·찾는 조건·근거를 한 줄씩 적고 근거 없는 패턴은 넣지 않는다.

**한 일**: 패턴 8개를 근거 한 줄씩과 함께 정리했습니다. 높은 위험도 경보, SQL 구문 반복, 스크립트 태그 반복, 경로 거슬러 올라가기 반복, 명령 구분자 연속, 주입 표식 반복, 반복 없는 주입 표기 1건(알림), 중간 위험도(알림)입니다.

## 제작 3: Jev 판단

**프롬프트가 시킨 것**: xdr-01과 같습니다. 패턴과 맞춰 본 뒤 애매한 건만 Jev에게 확신도를 받고, 0.85 이상은 block, 0.5 이상은 alert, 그 아래는 record입니다. Jev가 응답하지 않으면 alert로 떨어뜨립니다.

**한 일**: xdr-01에서 0점을 세 번 받고 배운 점을 처음부터 적용했습니다.
- `decide.mjs`는 다른 파일 없이 단독으로 동작하는 한 파일입니다(패턴 정의와 Jev 호출이 파일 안에 있음). 이 파일만 빈 폴더에 복사해서 돌려도 8/9/9가 나오는 시험이 있습니다.
- 위험도 10 이상은 차단, 5~9는 알림이라는 바닥 기준을 처음부터 넣었습니다.
- Jev는 확신도를 올리는 데만 쓰고, 오류나 낮은 값이면 alert를 유지합니다.

## 제작 4: 알림과 차단

**프롬프트가 시킨 것**: xdr-01과 같습니다. 차단 후보만 ZTNA 판정기의 거부 규칙으로 넣는 연결을 만들고, 규칙에 만료 시각과 근거 경보 번호를 붙입니다. 정상 사용자를 막는 규칙은 넣지 않고, 알림은 `xdr/alerts.log`에 한 줄씩 쌓습니다.

**한 일**: `respond.mjs`가 알림을 `xdr/alerts.log`에, 차단 후보를 `block-rules.json`에 적습니다(후보 주소 7개). xdr-01과 같은 이유로 판정기에는 연결하지 않고 파일로만 만들었습니다.

**같이 고친 것**: 두 모듈이 `xdr/alerts.log`를 덮어쓰는 문제가 있었습니다. 줄마다 `[모듈명]` 접두사를 붙이고 다른 모듈의 줄은 보존하도록 고쳤습니다. 처음 푸시한 커밋에는 이 교체가 한 줄 빠져 있었고, 두 번째 커밋(`21f6683`)에서 바로잡았습니다.

## 제출 전 확인

`보너스 xdr-02 저장점`으로 커밋하고 푸시했습니다. 시험은 변형 경보(다른 문구, 반복 없는 표기, 필드 누락)와 단독 실행, `patterns.json`과 `decide.mjs`의 패턴 정의가 같은지 확인하는 것을 포함해 15개(brute-force 포함)가 통과했습니다.

## 쉽게 풀면

xdr-01이 "비밀번호를 계속 틀리는 사람"을 찾는 것이었다면, xdr-02는 "검색 칸에 이상한 명령어를 계속 넣는 사람"을 찾는 것입니다. 한두 번 `select`나 `script` 같은 단어가 들어간 것은 수업에서 쓰는 단어일 수 있어서 알림만 남기고, 같은 주소에서 8~20번 반복되면 차단 후보로 올립니다.

- 판정자의 정답표는 보지 못했습니다. 같은 구조로 만들어 첫 제출에서 100점이 나왔지만, 기준이 같다는 보장은 없습니다.
