# 보너스 xdr-05: 권한 가로채기를 잡아 냅니다

커밋: 보너스 xdr-05 저장점
심판 결과: 아직 제출하지 않았습니다.

## 무엇이 문제인가

최 부장 PC의 평범한 계정이 갑자기 관리자 그룹에 들어가고 관리자 명령을 실행하기 시작했습니다. 정상 계정을 도용해 권한을 키우는 공격입니다. 실제 사고로 마이크로소프트 경영진 메일함까지 번진 미드나이트 블리자드 공격 사례가 소개됩니다.

만들 것은 계정·그룹 변경 경보와 관리자 권한 사용 경보를 모아, 평소와 다른 권한 상승을 알리고 명확한 경우에만 그 계정의 세션을 거둘 후보로 올리는 모듈입니다. 판정기 규칙을 대신하지 않습니다.

## 이어받기

README의 마지막 단계 기록(12단계 보완)과 마지막 커밋(보너스 xdr-04 저장점)이 어긋나지 않는 것을 확인했습니다. `xdr/privilege/`는 비어 있었고 경보 묶음은 26건(`xdr/fixtures/privilege.json`)이었습니다. 아무 파일도 고치지 않았습니다.

## xdr-03·04와 같은 원칙

심판이 인터넷 없이 `decide.mjs` 한 파일만 불러와 경보마다 바로 답을 받습니다.

- Jev를 부르지 않고, `decide.mjs`에 import 문이 없고, 파일·네트워크도 쓰지 않습니다. 패턴은 파일 맨 위 상수입니다.
- 읽기 모듈은 확인용이라 `decide.mjs`가 불러오지 않는 별도 파일입니다.
- 위험도 10 이상은 block, 5~9는 alert라는 바닥 기준을 처음부터 넣었습니다.

## 제작 1: 경보 읽기

**프롬프트가 시킨 것**: `xdr/fixtures/privilege.json`의 Wazuh 경보를 읽어 시각·출발 주소·계정·규칙 수준·설명만 뽑는 읽기 모듈을 `xdr/privilege/read-alerts.mjs`로 만든다. 원본 경보는 고치지 않고 비밀값처럼 보이는 값은 출력하지 않는다. 이 모듈은 확인용이라 `decide.mjs`가 불러오지 않게 따로 둔다. 확인: 경보 건수와 뽑은 줄 수가 같아야 한다.

**한 일**: 경보 26건에서 26줄을 뽑습니다. 그룹 이름 같은 나머지 값은 뽑지도 출력하지도 않습니다.

## 제작 2: 패턴 목록

**프롬프트가 시킨 것**: 이 공격의 알려진 형태를 `xdr/privilege/patterns.json`으로 정리한다. 근거는 MITRE ATT&CK T1068(권한 상승 악용), T1078(정상 계정 도용)이고 신호는 관리자 그룹 추가, 처음 보는 관리자 명령, 업무 시간 밖 권한 사용 정도다. 패턴마다 이름·찾는 조건·근거를 한 줄씩 적고 근거 없는 패턴은 넣지 않는다.

**한 일**: 패턴 9개를 근거 한 줄씩과 함께 정리했습니다.

| 패턴 | 확신도 | 뜻 |
|---|---|---|
| 관리자 그룹 추가 | 0.95 | 평범한 계정이 관리자 그룹에 추가되거나 다시 들어옴 |
| 방금 관리자가 된 계정의 활동 | 0.93 | 관리자가 된 직후 곧바로 관리자 명령 |
| 업무 시간 밖의 관리자 권한 사용 | 0.93 | 평소 일하지 않는 시각 |
| 처음 보는 주소의 관리자 권한 사용 | 0.93 | 낯선 주소에서 관리자 명령 |
| 다른 계정의 권한 사용 | 0.93 | 다른 계정의 권한으로 관리자 명령 |
| 높은 위험도의 권한 상승 경보 | 0.90 | 위험도 10 이상 |
| 관리자 권한 관련 활동 | 0.60 | 평소와 다르다는 근거가 없음 |
| 관리자 그룹이 걸린 경보 | 0.60 | 그룹 필드가 관리자 그룹 |
| 중간 위험도 경보 | 0.55 | 위험도 5~9 |

경보 묶음에는 "과제 그룹에 추가됐습니다. **관리자 그룹은 아닙니다**"라는 애매한 경보가 있습니다. "관리자 그룹"이라는 단어가 들어 있지만 부정하는 문장이라서, 단어만 보면 오탐이 납니다. 그래서 "관리자 그룹에 추가", "관리자 그룹에 들어가"처럼 동작이 붙은 표현만 확실한 신호로 보고, 단어만 있는 경우는 알림으로 두었습니다.

## 제작 3: 판정 모듈

**프롬프트가 시킨 것**: 패턴을 `decide.mjs` 맨 위에 상수로 옮겨 적고, 그 패턴과 경보를 맞춰 판단하는 `decide(alert)` 하나를 내보낸다. 반환은 `{action, confidence, reason}`이고 확신도 0.85 이상은 block, 0.5 이상은 alert, 그 아래는 record다. `reason`에는 근거 패턴 이름을 한 줄로 적는다. 다른 파일이나 패키지를 불러오지 않고, 파일을 읽거나 쓰지 않고, 바깥에 묻지 않고 혼자 계산한다. 확인: 명확한 공격은 block, 애매한 건 alert, 정상 이벤트는 record로 나뉘어야 하고 `decide.mjs`에 import 문이 없어야 한다.

**한 일**
- `patterns.json`과 같은 내용을 파일 맨 위 상수로 넣고 두 곳이 같은지 시험합니다.
- 경보 설명의 문구와, 경보의 그룹 필드가 관리자 그룹인지를 함께 봅니다. 계정·그룹 값은 판단에만 쓰고 결과에는 담지 않습니다.
- 서로 다른 강한 신호(확신도 0.85 이상)가 둘 이상 겹치면 확신도를 조금 올립니다.
- `decide`만 내보내고, 이유에는 패턴 이름만 담습니다.

## 제작 4: 알림과 차단

**프롬프트가 시킨 것**: `xdr/privilege/respond.mjs`를 새로 만들어 `decide` 결과 가운데 차단 후보만 ZTNA 판정기의 거부 규칙으로 넣는 연결을 만든다. 규칙에는 만료 시각과 근거 경보 번호를 붙이고 정상 사용자를 막는 규칙은 넣지 않는다. 알림은 같은 파일에서 `xdr/alerts.log`에 한 줄씩 쌓는다. `decide.mjs`는 판단 결과만 돌려주고 파일 쓰기·판정기 연결은 하지 않는다. 판정기의 기존 규칙은 고치지 않는다.

**한 일**: `respond.mjs`가 알림을 `[privilege]` 접두사로 `xdr/alerts.log`에 쌓고(다섯 모듈의 줄이 모두 보존됨), 차단 후보를 `block-rules.json`에 적습니다. 후보는 8개 주소이고 규칙마다 만료 시각(경보 시각 + 1시간)과 근거 경보 번호가 있습니다. 정상 판정이 난 주소는 후보에서 뺍니다.

**프롬프트와 다르게 한 점**: 프롬프트는 "그 계정의 세션을 거둔다"고 설명하지만, 판정기의 요청에는 접속 주소가 없고 세션을 거두는 연결도 계약에 없어서, 차단 후보는 파일로만 만들고 판정기에 연결하지 않았습니다(앞의 모듈들과 같습니다).

## 제출 전 확인

`npm run xdr:run -- privilege`를 다시 실행해 `result.json`을 갱신하고 「보너스 xdr-05 저장점」으로 커밋합니다. 시험 11개(`xdr/privilege/variants.test.mjs`)가 통과했습니다. 위험도가 낮아도 명확한 문구는 block, "관리자 그룹은 아닙니다" 같은 부정 문장과 관리자 명령 1건은 alert, 수업용 관리 계정의 평소 로그인은 record, 필드가 빠진 경보는 오류 없이 record인지, 파일 하나만 복사해도 9/8/9인지, 소스에 import·파일·네트워크 사용이 없는지 확인합니다.

## 쉽게 풀면

평범한 계정이 갑자기 관리자가 되는 것이 이 공격의 핵심입니다. 관리자 그룹에 들어가자마자 관리자 명령을 실행하거나, 평소 일하지 않는 시각에 처음 보는 주소에서 관리자 권한을 쓰거나, 남의 계정 권한을 빌려 쓰면 확실한 공격으로 봅니다. 수업 중 권한 상승 창이 한 번 뜬 것이나 관리자 그룹이 아닌 그룹에 추가된 것, "수업용 관리 계정이 평소 주소에서 로그인"하는 것은 공격이 아닐 수 있어서 알림이나 기록만 남깁니다.

## 하지 못한 것과 남은 약점

- 차단 후보를 ZTNA 판정기에 실제로 연결하지 않았고, 계정의 세션을 거두는 동작도 만들지 않았습니다. 후보는 파일로만 있습니다.
- 판정자의 정답표는 보지 못했습니다. 우리 기준이 정답표와 같다는 보장은 없습니다.
- 경보 설명의 문구를 근거로 하므로, 같은 뜻을 전혀 다른 표현으로 쓴 경보는 위험도 바닥 기준(10 이상 block, 5~9 alert)에 기댑니다.
